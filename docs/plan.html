Google Trends 데이터를 GitHub Actions로 주기적으로 수집하고, 정적 웹사이트에서 기간·국가·카테고리별 트렌드와 관련 뉴스를 확인합니다.

작업 계획 + 인터랙티브 UI 목업

01. 데이터를 가져올 수 있나요?

네. 실제 Google Trends 페이지 응답에서 데이터를 확인했습니다. 한국 48시간 응답에서 244개 항목을 파싱 가능한 형태로 확인했습니다. 이는 검증 당시 건수이며 고정 개수가 아닙니다.

방법용도 / 판단
페이지 내 초기 JSON 데이터주 수집 방식. HTML의 AF_initDataCallback 데이터를 JSON으로 읽습니다. 검색어, 국가, 시작·종료 시각, 검색량, 증가율, 관련 검색어, 카테고리 ID를 확인했습니다. 원격 스크립트를 실행하지 않습니다.
Google 제공 RSS관련 뉴스 기본 소스. 실제 한국 RSS에서 검색어 10개와 검색어별 기사 제목·언론사·원문 URL·이미지를 확인했습니다. RSS에 포함된 검색어를 정확히 매칭하고, 저장한 뉴스도 검색어별로 재사용합니다. RSS만으로 기간별 전체 목록을 대체하지 않습니다.
공식 CSV 내보내기수집 결과 대조용. Google 화면의 같은 국가·기간 데이터와 비교합니다.

페이지 내부 JSON은 문서화된 공식 API가 아닙니다. 데이터 형식이 바뀌면 검증에서 실패 처리하고 마지막 정상 수집본을 유지합니다. 한국 RSS의 뉴스 필드는 확인했습니다. RSS에 없는 검색어의 뉴스 확보 방식과 국가별 카테고리 매핑은 추가 검증이 필요합니다. RSS의 검색어 pubDate를 기사 발행 시각으로 사용하지 않습니다.

참고: Google 공식 Trending now 도움말 · 확인한 한국 48시간 원문

02. 확정할 기능 범위

기능동작 계획완료 기준
기간별 조회4·12·24·48시간·7일. 12시간은 24시간 목록에서 시작 시각으로 필터링12시간 검색량·증가율이 24시간 원본 값임을 명확히 표시
국가 선택초기 한국·미국·일본, 설정 파일로 국가 추가국가별 파일·캐시·신규 비교·히스토리 분리
검색·필터·정렬검색어·관련 검색어 검색, 카테고리, 상승 중, 검색량·증가율·최신순다중 카테고리 지원, 미확인 ID는 기타로 표시하고 원본 ID 보존
관련 뉴스검색어 선택 시 제목·언론사·이미지·원문 링크 표시. 기사 발행 시각은 확인된 경우만 표시검증된 매칭 기사만 표시. 기사 없으면 없음 안내와 뉴스 검색 링크 제공
자동 갱신·신규화면은 5분마다 최신 정적 파일 확인. 신규는 동일 국가·원본 기간의 직전 성공 스냅샷 대비 최초 등장첫 수집은 기준선으로 처리. 새 데이터가 없으면 신규 재계산 안 함
CSV / JSON현재 필터 결과 내보내기. Explore는 출처·조건·Top/Rising·상대 점수·성장률·Breakout을 별도 열로 보존. 한국어 CSV BOM·셀 수식 방지조회 조건·원본 기간·수집 시각·시간대 포함
히스토리30분 단위 스냅샷 30일, 일별 요약 180일 보관과거 시점 선택, 검색어별 관측 검색량·등장 기록 확인

히스토리는 프로그램 가동 이후 수집분부터 쌓입니다. 관측값의 변화는 Google의 과거 시간별 실제 검색량과 다르므로 누적하거나 합산하지 않습니다.

02-1. Explore 기간 분석 — 추가 요청

지난 1주·지난 1달·지난 3개월·지난 1년과 상위 검색어·급상승 검색어를 추가합니다. 기존 Trending now와 별도 Explore 모드로 구성합니다. 사용자가 제공한 Explore 링크를 기준으로 국가·기간·카테고리·선택 검색어를 수집 조건에 반영합니다.

선택 항목데이터 기준
지난 1주Explore 원문 · date=now 7-d
지난 1달사용자 제공 Explore 원문 · date=today 1-m
지난 3개월Explore 원문 · date=today 3-m
지난 1년사용자 제공 Explore 원문 · date=today 1-y
상위 검색어 (Top)선택 조건에서 Google이 제공하는 상위 검색어와 상대 점수. 실제 검색 횟수로 표시하지 않습니다. 기준 검색어가 있으면 해당 검색어의 관련 검색어입니다.
급상승 검색어 (Rising)이전 비교 기간 대비 성장률과 Breakout(폭발적 증가). Google 설명상 5,000% 초과 증가를 Breakout으로 표시하며, 이를 임의의 숫자로 바꾸지 않습니다.

지난 1년 조회는 Explore가 반환하는 해당 기간 분석 결과를 사용하므로 서비스 자체 이력이 1년 쌓일 때까지 기다릴 필요는 없습니다. 자체 수집 스냅샷은 기존 180일 보관 정책을 유지하며 이와 구분합니다. 기준 검색어 없이 전체 검색어 조회를 우선하고, 선택적으로 기준 검색어를 입력해 관련 검색어를 분석합니다. 국가·기간·카테고리·기준 검색어·검색 유형이 같은 조건에서 Top/Rising을 전환합니다. 응답에 결과가 없으면 미제공 또는 데이터 부족 상태를 표시합니다.

Explore 자동 수집은 별도 검증 단계입니다. 제공된 URL은 확인했으나 현재 웹 도구로 페이지 본문을 읽지 못했으므로 실제 Top/Rising 응답 수집 성공을 의미하지 않습니다. Trending now의 hours 값을 늘리거나 누적 스냅샷을 합산해 월간 순위를 만들지 않습니다. 구현 시 Explore 요청 방식·세션·제한·응답 구조를 검증하고, 실패 시 마지막 정상 결과와 원문 링크를 제공합니다.

공식 근거: 상위·급상승 검색어의 의미 · 지난 1달·3개월 기간 지원 · 상대 지표와 정규화

수집 운영

  • 예약식 17,47 * * * * (UTC). 매 정각 혼잡을 피하되 실제 실행 시각은 지연될 수 있습니다.
  • Trending now: 국가 3개 × 원본 기간 4개(4·24·48·168시간), 12시간은 파생하여 중복 요청을 줄입니다. Explore: 국가 3개 × 기간 4개(1주·1달·3개월·1년)의 Top/Rising을 별도 수집합니다. 초기에는 전체 카테고리·기준 검색어 없음·웹 검색 조건으로 수집합니다.
  • Explore는 하루 1회(UTC 00:23 / KST 09:23) 별도 job으로 수집하고 수동 갱신도 지원합니다. 카테고리·기준 검색어 조건은 설정에 등록한 조합만 예약 수집합니다. 정적 사이트에서 미수집 조합은 수집된 조건이 아님을 안내하고 Google 원문으로 연결합니다.
  • 타임아웃, 제한된 재시도와 지수 백오프. 429 응답은 Retry-After를 존중합니다.
  • 동시 실행을 제한하고 국가·기간마다 성공 시각을 기록합니다.
  • 실패한 구간은 덮어쓰지 않고 경고와 마지막 성공 시각을 표시합니다.

저장·배포

  • 소스는 main, 데이터는 별도 data 브랜치. 성공한 변경만 커밋합니다.
  • 수집 워크플로 안에서 데이터 저장 후 Pages artifact 업로드·배포까지 수행합니다. 봇 커밋에 따른 재실행에 의존하지 않습니다.
  • 배포 권한은 필요한 job으로 제한하고 외부 Action은 커밋 SHA로 고정합니다.
  • 프런트엔드는 정적 파일만 읽습니다. 브라우저에서 Google에 직접 요청하지 않습니다.
  • 장기 사용 시 Git 이력의 용량도 점검합니다. 파일 삭제만으로 이전 커밋 용량이 줄지 않으므로 필요 시 객체 저장소로 전환합니다.

검색어 데이터: id, keyword, country, startedAt, endedAt, volume, growth, related, categoryIds, news[], firstSeenAt, isNew. 뉴스 데이터: title, url, publisher, publishedAt, fetchedAt, source. 신규 비교용 ID는 국가와 정규화 검색어로 만들고 원문을 함께 보존합니다. 재등장은 신규와 구분할 수 있도록 firstSeenAt과 직전 포함 여부를 따로 저장합니다.

모든 저장 시각은 UTC ISO 8601, 기본 화면 시각은 Asia/Seoul. GitHub 프로젝트 Pages의 하위 경로에서도 동작하도록 상대 URL을 사용합니다.

06. 구현 순서와 검증 기준

  1. 수집 타당성 검증: KR/US/JP 각 시간대 JSON 파싱, Google CSV와 표본 대조, 카테고리 ID 매핑, RSS 뉴스 매칭률과 미국·일본 뉴스 필드 확인. Explore 1주·1달·3개월·1년의 Top/Rising 수집을 검증하고 동일 조건 Google 화면/CSV와 비교합니다. 날짜 파라미터 now 7-d, today 1-m, today 3-m, today 1-y를 그대로 사용하고 임의의 7·30·90·365일 범위로 치환하지 않습니다. 기준 검색어 없는 조회 및 데이터 부족 응답도 확인합니다. 뉴스가 부족하면 별도 뉴스 검색 소스 도입 여부를 결정합니다.
  2. 수집기·저장: 스키마 검증, 직전 성공분 비교, 원자적 파일 교체, 부분 실패 복구, 보관 정책과 날짜 인덱스를 구현합니다.
  3. 화면: 목업을 기준으로 기간·국가·필터·정렬·검색·뉴스·내보내기·히스토리를 연결합니다. 빈 결과, 로딩, 오래된 데이터 표시와 모바일·키보드 사용을 점검합니다.
  4. 자동화: 수동 Actions 실행으로 수집→커밋→Pages 배포를 확인하고 예약을 활성화합니다. 배포 URL에서 JSON 로딩과 프로젝트 하위 경로를 검증합니다.
  5. 인수 검증: 12시간 경계, 중복·재등장, 국가 변경, 429·타임아웃·HTML 변경, 뉴스 없음, CSV 특수문자, 30일 보관 정리, 동시 실행과 배포 실패를 테스트합니다. Explore의 날짜 표현식 전달, Top/Rising 전환, Breakout과 0·null 구분, 조건별 캐시 격리, 지표 단위, 뉴스 기간 표시, 내보내기 출처, 모바일 목업 표시도 검증합니다.
