설계 결정

항목선택이유
저장소GitHub 비공개 저장소 (개인 계정 소유)코드 비공개. Vercel Hobby는 조직(Organization) 소유 비공개 저장소는 연결할 수 없어 개인 계정 소유여야 함
수집 언어Python 3.12 (표준 라이브러리 + requests)의존성이 적고 Actions 러너에 기본 설치되어 있음
데이터 저장같은 저장소의 public/data/ 폴더DB가 필요 없음. git 이력이 곧 히스토리 백업. public/ 아래라 그대로 정적 파일로 제공됨
프론트엔드Vanilla JS + 단일 HTML (빌드 없음)규모가 작아 프레임워크 불필요. Vercel이 빌드 없이 public/을 바로 배포
배포Vercel Git 연동 (Framework: Other, 출력 폴더 public)push마다 자동 배포되어 Actions에 배포 단계가 필요 없음 → Actions 사용 시간 절약, 토큰·시크릿도 필요 없음
주기2시간 (7 */2 * * *)비공개 저장소의 Actions 무료 한도는 월 2,000분. 2시간 주기면 월 360회 × 약 2분 = 약 720분으로 여유 있음. 정각에 몰리면 지연되기 쉬워 7분으로 어긋나게 설정
캐시vercel.json에서 /data/*는 max-age=0, must-revalidate새로 배포하면 최신 JSON이 바로 보이도록 함. HTML/JS는 기본 캐시 유지
Vercel Hobby 한도: 하루 배포 100회, 월 대역폭 100GB, 개인·비상업 용도에 한함. 이 프로젝트는 하루 12회 정도 배포하므로 충분합니다.

3-1. 탐색 데이터: 상위 · 급상승 검색어 2026-10-01 호출 검증 완료

Google 트렌드 탐색 페이지(explore?geo=KR&date=today 1-m 등)의 “사람들이 많이 검색한” 영역에 나오는 데이터입니다. 새 탐색 화면은 로그인해야 보이지만, 기존 탐색 API를 쓰면 로그인 없이 같은 데이터를 받을 수 있습니다.

기간탐색 페이지 주소의 dateAPI time 값비교용 직전 기간(순위 변동 계산)검증 결과
지난 1주now 7-dnow 7-d그 전 7일 (YYYY-MM-DD YYYY-MM-DD)상위 25 · 급상승 25
지난 1개월today 1-mtoday 1-m그 전 1개월상위 25 · 급상승 17
지난 3개월today 3-mtoday 3-m그 전 3개월상위 25 · 급상승 11
지난 1년today 1-ytoday 12-m그 전 12개월상위 25 · 급상승 25

호출 순서

1) GET https://trends.google.co.kr/explore?geo=KR&hl=ko          # 세션 쿠키 NID 받기 (없으면 429)
2) GET /trends/api/explore?hl=ko&tz=-540&req=
       {"comparisonItem":[{"geo":"KR","time":"today 1-m"}],"category":0,"property":""}
   → widgets 중 id == "RELATED_QUERIES" 의 request, token
3) GET /trends/api/widgetdata/relatedsearches?hl=ko&tz=-540&req=<request>&token=<token>
   → default.rankedList[0] = 상위 검색어  { query, value(0~100 관심도) }
     default.rankedList[1] = 급상승 검색어 { query, value(증가율 %), formattedValue("+3,750%" | "급등") }
   (응답 앞의 )]}' 접두어는 잘라내고 파싱)
“변경” 열: Google 새 탐색 화면의 “변경 −30%”는 API에서 받을 수 없습니다. 대신 직전 같은 길이 기간의 상위 25개를 한 번 더 받아서 순위 변동(▲3 / ▼1 / NEW)으로 보여줍니다. 목업의 순위 변동은 이 방식으로 계산한 실제 값입니다.
카테고리 · 검색 유형: category(예: 스포츠 20, 엔터테인먼트 3)와 property(""=웹, news, youtube, images, froogle=쇼핑)를 바꿔 조회할 수 있습니다. 조합마다 요청이 늘어나므로 v1에서는 “모든 카테고리 · 웹 검색”만 수집하고, 나머지는 v2에서 검토합니다.

수집 주기

기간이 1주 이상이라 하루에 한 번이면 충분합니다. 2시간마다 도는 워크플로 안에서 오늘 날짜 파일이 이미 있으면 건너뛰도록 합니다. 하루 요청 수는 4개 기간 × (explore + relatedsearches) × (현재 + 직전 기간) = 16회이고, 요청 사이에 1.5초 간격을 둡니다.

7. 워크플로·배포 설정 초안

.github/workflows/fetch.yml

name: fetch-trends
on:
  schedule: [{ cron: "7 */2 * * *" }]  # 2시간마다 7분 (UTC)
  workflow_dispatch:

permissions: { contents: write }
concurrency: { group: fetch-trends, cancel-in-progress: false }

jobs:
  fetch:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12", cache: pip }
      - run: pip install -r requirements.txt
      - run: python scripts/fetch_trends.py --geo KR,US,JP --hours 4,24,48,168
      - run: python scripts/explore.py --geo KR --periods 7d,1m,3m,12m --once-per-day
        continue-on-error: true   # 탐색 수집이 실패해도 실시간 데이터는 커밋
      - name: Commit & push (push되면 Vercel이 자동 배포)
        run: |
          git config user.name  "${{ vars.COMMIT_NAME }}"
          git config user.email "${{ vars.COMMIT_EMAIL }}"   # 본인 GitHub noreply 이메일
          git add public/data
          git diff --cached --quiet || git commit -m "data: $(date -u +%FT%H:%MZ)"
          git pull --rebase && git push

Hobby 플랜 주의: 비공개 저장소에서는 커밋 작성자가 Vercel 계정과 연결된 본인 GitHub 계정이어야 배포가 진행됩니다. github-actions[bot] 같은 봇 이름으로 커밋하면 “commit author did not have contributing access” 오류로 배포가 막힙니다. 그래서 커밋 작성자를 본인 GitHub noreply 이메일(ID+username@users.noreply.github.com)로 설정합니다. 이 방법이 막히면 대안으로 Actions에서 vercel deploy --prod --token $VERCEL_TOKEN으로 직접 배포하고, 이 경우 실행 1회당 약 30초가 더 듭니다.

9. 리스크와 대응

리스크영향대응
비공식 API 형식 변경높음파서가 실패하면 기존 latest를 덮어쓰지 않고 워크플로를 실패 처리 → 이슈 생성. 백업 경로로 트렌드 RSS(상위 10건)만이라도 저장
탐색 API 429 (쿠키·IP 기반 제한)중간쿠키를 먼저 받고 하루 16회만 호출. 실패하면 전날 데이터를 유지하고 화면에 “기준일”을 표시. 계속 막히면 Actions에서 Playwright 헤드리스 브라우저로 호출하는 방식으로 전환
GitHub 러너 IP 차단·요청 제한중간요청 수 최소화(국가 3 × 기간 4 = 12회 + 뉴스). 429 응답이면 지수 백오프로 재시도. 뉴스는 캐시해서 이미 가져온 키워드는 다시 조회하지 않음
cron 지연·누락낮음화면에 수집 시각을 표시해 오래된 데이터임을 알 수 있게 함. 3시간 넘게 갱신이 없으면 경고 배너 표시
Actions 무료 한도(월 2,000분) 초과낮음2시간 주기 기준 월 약 720분. 뉴스는 이미 가져온 키워드면 다시 조회하지 않고, timeout-minutes: 10으로 실행이 길어지는 것을 막음
Vercel Hobby에서 봇 커밋 배포가 막힘중간커밋 작성자를 본인 계정으로 설정. 그래도 안 되면 Actions에서 Vercel CLI로 직접 배포
저장소 용량 증가낮음히스토리 압축 저장 + 월 단위 gzip. 연간 100MB 미만 예상
Google 이용약관중간개인·비상업용, 낮은 빈도로만 수집. 페이지에 출처(Google 트렌드) 표기와 원본 링크 제공
